Rerank

Rerank 重排序系统

通过 CrossEncoder 交叉编码器对初步检索结果进行二次精排，显著提升结果相关性

🎯

设计目标

在 RAG 检索场景中，向量相似度搜索（Embedding + L2 距离）虽然能快速召回候选文档，但召回精度有限。Rerank 系统通过引入 CrossEncoder 交叉编码器对初步检索结果进行二次精排，显著提升最终返回结果的相关性。

📐 技术方案流程

🔤 用户 Query
→
📊 Embedding 向量化
→
🔍 Chroma 向量检索
L2 距离 → 相似度
→
📋 Top-K 候选
→
⚡ CrossEncoder 重排序
→
📈 Sigmoid 归一化
→
✅ 阈值过滤 & 排序
⚙️

模型初始化

_init_cross_encoder 方法：

  • 使用 sentence_transformers.CrossEncoder 加载本地重排序模型
  • 模型路径通过 RAGConfig.rerank_model_path 配置
  • 自动检测 CUDA 可用性，优先使用 GPU 加速
  • 模型初始化失败会终止服务启动
📊

重排序流程

_rerank_results 方法：

  • 构建 Query-Document 对
  • CrossEncoder 打分（原始分数 -10 ~ 10）
  • Sigmoid 归一化到百分制 (0-100)
  • 阈值过滤（默认 60 分）
  • 按重排序分数降序排列
Python — 核心流程伪代码 store.py
def _rerank_results(query, results): # 1. 构建 Query-Document 对 pairs = [(query, result['document']) for result in results] # 2. CrossEncoder 打分（原始分数通常在 -10 ~ 10 之间） scores = cross_encoder.predict(pairs) # 3. Sigmoid 归一化到百分制 (0-100) scaled_scores = [1 / (1 + exp(-score)) * 100 for score in scores] # 4. 阈值过滤（默认 60 分） filtered = [r for r, s in zip(results, scaled_scores) if s >= threshold] # 5. 按重排序分数降序排列 return sorted(filtered, key=lambda x: x['rerank_score'], reverse=True)

VectorEmbedder 向量化

📁 文件位置：nanobot/knowledge/vector_embedder.py

基于 sentence-transformers 库实现本地文本向量化，无需外部 API 调用。

  • 使用 SentenceTransformer 加载本地 Embedding 模型（如 BAAI/bge-large-zh-v1.5）
  • 支持单文本 (embed_text) 和批量 (embed_batch) 向量化
  • 空文本自动返回零向量，保证系统健壮性
  • 模型加载失败抛出 EmbeddingModelError，提供详细的排查指引
✂️

TextChunker 分块

📁 文件位置：nanobot/knowledge/text_chunker.py

基于 langchain_text_splitters.RecursiveCharacterTextSplitter 实现智能文本分块。

分隔符优先级（从高到低）：

1 CHUNK_BOUNDARY（手动标记）
2 代码块
3 段落 (\n\n)
4 中文句号/问号/感叹号 → 英文句号/问号
5 中文逗号 → 英文逗号 → 空格 → 字符级分割
  • 支持 CHUNK_BOUNDARY 手动分块标记，精确控制分块边界
  • 中文友好的分隔符配置，优先在语义完整的边界处分块
  • 自动过滤内容过少（< 10 字符）的碎片分块
  • 短文本（≤ chunk_size）不分块，直接返回

意图分类系统

A/D 两级分类 + 两阶段匹配，精准路由用户请求

📖

A 类 — 知识问答

纯知识性问题，交由 LLM 直接回答。通过关键词模式匹配快速识别。

是什么 什么是 介绍一下 解释一下 有什么区别 原理 what is explain
🔧

D 类 — 操作/排查

需要执行具体操作的请求，进入 Skill 执行流程。采用两阶段匹配策略。

Atomic Skill（原子技能）单工具封装

对单次工具调用的结构化封装，本身不包含业务逻辑。

YAML — check_disk_usage.yaml atomic
name: check_disk_usage version: "1.0" type: atomic description: "检查磁盘使用率" input_schema: node_name: string output_schema: disk_usage: number mount_point: string execution: steps: - tool: check_disk_usage # 绑定 ToolRegistry 中的工具
📋

SOP Skill（标准操作流程）多步骤编排

编排多个 Atomic Skill + 规则引擎 + LLM 总结的完整排障工作流。

YAML — disk_full_diagnosis.yaml sop
name: disk_full_diagnosis version: "1.0" type: sop description: "磁盘满故障诊断" input_schema: node_name: string steps: - id: check_disk type: skill skill: check_disk_usage input: node_name: "{{node_name}}" - id: determine_cause type: root_cause_definition logic: - when: { disk_usage: ">90" } root_cause: "磁盘使用率超过 90%" solution: "清理日志文件或扩容磁盘" - id: summary type: llm prompt: "根据检查结果生成诊断报告..." input_from: - check_disk.disk_usage - determine_cause.root_cause
⚙️

RCAEngine 执行引擎

📁 nanobot/rca/engine.py

按 Skill YAML 中定义的 steps 列表顺序执行排障工作流。

四种步骤类型

步骤类型执行方式说明
skill 查找 Atomic Skill → 解析输入 → 安全校验 → 执行 → 校验输出 通过 Atomic Skill 间接调用工具
tool 解析输入 → 安全校验 → ToolRegistry 直接执行 直接调用 ToolRegistry 中的工具
llm 解析引用 → 渲染 Prompt → 单轮 SLM 调用 → 解析 JSON 独立的 LLM 调用，最小上下文
root_cause_definition 收集前置步骤输出 → 遍历规则 → 条件匹配 → 输出根因 确定性规则引擎，不依赖 LLM

步骤间数据传递 (StepContext)

📝 input 模板映射
